# 引擎LOD架构

Bevy 运行时的本机 LOD。当前地形 LOD 几何体连接
`WORLD_LAYER`，所以它出现在水中倒影经过设计
（`render.rs`、`REFLECTION_VIEW_LAYERS`）；反思成本是有预算的。

## 混合物体方向

[比尔的提案](https://github.com/Mudcrab-Team/mudcrab/issues/203) 和
[泰勒协议](https://github.com/Mudcrab-Team/mudcrab/issues/203#issuecomment-6086560142)
在本机 LOD 中添加集群 LOD 实验。方向是
基于网格优化器的集群选择与间接绘制，以及创作
并自动生成常规LOD。它不选择Bevy's
实验性网格渲染器。

将四项责任分开：世界居住权决定来源
对象可用；资格和州决定哪些可以提供；
几何细节选择一种表示；绘制提交发送其可见的
工作到后端。集群细节必须重用本机流、验证、
每个对象的身份和可绘制的切换。它不能成为另一个世界或
游戏状态所有者。地形、小网格、树木和无支撑材料
家庭保留专用路线；空间 HLOD 仍然是以后的选择
减少结算批次。

[混合对象 LOD 合约](hybrid-object-lod.md) 记录建议的有效负载，
能力、后备和接受选择。这些选择需要审查；
该协议授权原型设计，而不是成品渲染器或默认渲染器
改变。反射通过具有平面回退的 SSR 独立进行，
然后是带探针的 SSR 和禁用平面相机，每个都有自己的门。

## 层级模型

修复了超过完整细节网格的空间层：4、8 和 16 单元块
（`side_cells` 2016 年 4 月 8 日，DynDOLOD GEOM-01）。块大小、网格源、距离
策略和变体保持独立的维度（ARCH-03）。每个世界空间的 LOD
起源锚块；楼层除法向负无穷大舍入，因此
位置就在单元格 -1 (GEOM-02) 中的零地以西。 `worldspaces` 需求
世界数据库模式 6 中的原始列。

地形选择仍然基于层级。建议的对象实验选择
居住政策内预计几何误差的详细信息；它没有
替换地形层、块索引或完整细节网格。块大小，
对象绘制范围和簇的错误阈值保持独立。

## 流媒体集成

`plan_cells`/`collect_cells` 具有代保护功能的单电池密钥
过时的丢弃和每帧一次的默认提交
（`max_cell_commits_per_frame`，在 `EngineConfig` 中可调）。块获得并行键空间
`(world, tier, anchor)` 共享相同的提交预算和纪元处理，
如此快速的旅行无法搁浅半载的块。卸载使用迟滞：
仅当相机离开层范围加上边缘环时才删除层，因此
边界振荡不会冲击载荷。
每层在其自己的范围内查询、承认、保留和卸载，再加上两个
细胞。默认范围为 12/25/91 个单元格，即 14/27/93 个单元格
第 4/8/16 层。粗略层保留内部覆盖范围以供回退，而更精细的数据则保留
待处理或不可用。

## 距离配置（Skyrim INI 奇偶校验）

层级范围和完整细节网格使用《天际》自己的设置名称，因此值
玩家、模组管理器或 LOD 生成器为《Skyrim》保留不变。
`--ini <path>` 读取 `Skyrim.ini`/`SkyrimPrefs.ini` 格式的文件；文件适用
按照给定的顺序，后面的文件逐个键覆盖前面的文件，并且显式
命令行选项覆盖每个文件（无论它们出现在何处）
（`crates/engine/src/skyrim_ini.rs`）。

|部分|关键|效果|
|---|---|---|
| `[General]` | `uGridsToLoad` |全细节网格：`stream_radius = (uGridsToLoad - 1) / 2`；仅奇数值 |
| `[TerrainManager]` | `fBlockLevel0Distance` |乘数之前达到 4 级 |
| `[TerrainManager]` | `fBlockLevel1Distance` |乘数之前达到 8 级 |
| `[TerrainManager]` | `fBlockMaximumDistance` |在乘数之前达到 16 级 |
| `[TerrainManager]` | `fSplitDistanceMult` |三个街区距离的地形乘数 |

层在小区中的覆盖范围是 `floor(block distance * fSplitDistanceMult / 4096)`，
与距相机单元的切比雪夫单元距离相比，因此每个
层覆盖了相机周围的方形单元格。地形乘数遵循 DynDOLOD 的定义：对象 LOD
距离乘以 `fSplitDistanceMult` 给出地形 LOD 距离。对象细节层次
（第 2 阶段）将读取相同的三个块距离，无需乘数。

默认值是天际特别版自己的`SkyrimPrefs.ini`值：35000，
70000 和 250000 乘以 1.5
([步骤](https://stepmodifications.org/wiki/SkyrimSE:SkyrimPrefs_INI/TerrainManager)),
达到12/25/91个细胞。测量了初始地形切片并
在 4/8/16 单元范围内接受（`fSplitDistanceMult=1`，具有块距离
16384/32768/65536）。 [`cb617fc0` 候选者](../../research/lod-rc-20261002.md)
在《天际》默认设置下得到视觉批准；在该范围内的性能是
已推迟且尚未进行测量。通过 `--ini` 将旧值传递给
重现早期运行。
相机远平面遵循最大配置范围。

尚未兑现：32级地形（无编译层），`fTreeLoadDistance`
（第3阶段），`uLargeRefLODGridSize`（省略大量参考文献），以及
《天际》质量自行预设。引擎不会搜索用户的
`My Games` INI 文件；启动器或脚本显式传递它们。

切换：每个GLB块都有一个稳定的源单元节点，并且分别
可隐藏的地形和对象组，以及下面兼容的材质批次
每组。仅当匹配完整单元格或更接近单元格时，组才会隐藏其 LOD
层已通过场景/依赖项验证并且
已准备好展示；单独使用 `CellStatus::Resident` 是不够的。第二阶段
必须解决混合就绪或失败的近模型组如何过渡的问题
没有漏洞或重复。界限是保守的，包括所有
发出的组件，跨块和世界边界进行测试（GEOM-05/06，
运行-07）。

失败策略：保留瞬时块 I/O 错误的元数据；最多排队
在共享提交预算和当前的范围内，1/2/4 秒后重试三次
一代。丢失的有效负载、哈希不匹配和无效的场景内容仍然存在
终端。现有的准备好的粗略数据仍然有资格进行切换。贝维 0.19
`AssetServer::load` 同步重启观察到的故障资产；避免
从异步 `reload` 轮询缓存的失败作为新的尝试。
合成时钟调度和文件哈希装置涵盖分类、
重复队列预防和重试边界。端到端读卡器故障注入
目标硬件恢复捕获仍在验收工作中。

屏幕截图准备等待排队加载并重试并拒绝当前
未恢复的块/查询失败。成功恢复不会阻止 PNG。
烟雾捕获脚本仍然需要零累积 LOD 失败：它们
证明无故障运行，而不是恢复。恢复接受需要单独的故障注入
记录失败、验证有界重试和最终结果的协议
可绘制的覆盖范围，并且不会擦除累积的诊断信息。

共享提交上限不变。待处理的 LOD 工作保留一次提交
当上限超过 1 时；在第一章中，附近单元格和 LOD 交替优先。
仅当单元交叉属于以下时才保留不可变的排队块元数据
当前的世界空间并仍在范围内。旧的查询响应仍然存在
被一代人抛弃。仅短暂的 SQLite 繁忙/锁定/IO 失败重试
同一代中1/2/4秒后最多3次。无效
元数据已终止并保持故障关闭状态；持续性故障仍然可见
累积诊断和未恢复的仪表。

## 相机、阴影、雾

目前相机远的是`CELL_SIZE * (stream_radius + 2) * 2`（`app.rs`），
默认半径 2 处有 32,768 个单位。地形 LOD 块到达后
扩展到覆盖最大的配置层范围 (`streaming/lod.rs`)。太阳阴影级联源自
相同的半径。 LOD范围必须与远平面和雾相配合；遥远的
阴影覆盖需要其自身的质量和成本决定。 `SkyrimClear`雾
在 53,289 个单位 (`sky.rs`) 处达到最大数量 0.85，因此它不会
使超出该距离的几何体不可见。请参阅
[0期证据](../../research/lod-phase0-evidence.md)。

## 渲染路径

- 当前地形 LOD 网格使用相同的 GPU 预处理、间接绘制和渲染
  HZB 路径为完整几何形状；现有证明桥（`render.rs`）
  涵盖它们，没有特殊情况。
- 提出了对象簇选择及其间接命令路径的工作，
  与现有的桥梁分开。探头适配器功能；提供一个
  没有 GPU 绘制计数支持的有界金属路径。缓冲区溢出必须
  保留完整的粗略表示，永远不要默默地省略几何图形。
- 广告牌获得专用材质（参见 `billboard-generation.md`）。
- 动态代理是具有距离/状态系统的普通实体（参见
  `lod-runtime-proxies.md`)，空间分桶，从不全场景扫描
  每帧（RUN-05）。

### 第 0 阶段：完成已批准的合同

以下政策选择已获得批准。初始切片实现
地形节点身份、设置分辨率、构建身份、资产锁定和
参考状态元数据。对象组准备就绪，完整的恢复证明，
更广泛的视觉接受度仍然是较晚的大门：

- 保留 ADR-0010 文件支持的 GLB 和 R 树方向。使用稳定的
  具有可单独隐藏地形和对象组的源单元节点，
  在每组下面批处理兼容的材料。识别没有节点
  依赖于遍历顺序。定义地形/对象组准备情况和
  使用两小区的故障切换，
  两种材料的夹具；常驻根是不够的。
- 仅在 v1 引擎停止时发布。从不可变的构建
  输入边界，跨数据库、清单和块携带一个构建标识，
  验证完整的分阶段集，并保留最后的良好输出
  失败。活体资产置换不在范围之内。指定如何离线
  边界是强制执行的，以及之前如何恢复中断/回滚
  改变世界数据库模式。
- 使用有效的 `lodsettings/<worldspace>.lod` 作为安装的原始源
  世界。自定义世界可以提供明确的每个世界空间起源。如果
  两者都无效，跳过该世界的 LOD 并出现可操作的错误；从不
  默默地假设为零。对负块坐标使用楼层划分。
- 开始对象编译已验证，无条件启用固定
  参考文献，最初是一个狭窄的 `STAT` 类。提取参考标头标志
  和 XESP 父/反转，因此最初禁用或启用依赖记录
  由于原因而被省略，而不是被烘焙成静态块。
- 根据投影误差、相机距离、天气和天气情况确定可见范围
  测量的成本。保持远距离阴影覆盖范围独立于相机远距离；
  分别测量主通道和反射通道。雾的 0.85 上限不是
  能见度截止。使用脚本化的匹配捕获和目标硬件
  通过分析来设置数字预算，而不是在这里发明它们。

Gate：记录剩余的故障/恢复机制，稳定的节点身份，
和测量协议；检查两单元夹具设计。无运行时间
第 0 阶段的行为发生变化。第 1 阶段保持关闭状态，直到这些被接受。

### 第 1 阶段：证明地形和共享流

构建离线输入/发布合约、版本化块元数据和
R 树、经过验证的 GLB 有效负载路径和历元安全流。编译一个粗略的
来自单元缓存的地形环超出了完整细节卸载环。保存
负网格锚定、保守边界和声明的接缝/裙边策略。
当其完整地形或更近时，切换必须仅隐藏被覆盖的源单元
层是可绘制的，然后在加载失败或取消时恢复。

门：两单元夹具通过负载、故障、
卸载、传送和层转换，没有持久的漏洞或重复。
新鲜脚本地形捕捉显示没有不可接受的接缝。数据库、清单和
GLB 身份检查拒绝丢失或混合代；中断的构建
保留最后一个有效输出可用。记录匹配帧 P95/P99、加载延迟、
内存、图元数量、主/反射 GPU 成本（如果可用）和附近
与阶段 0 基线相比的阴影质量。不处理不可用的 GPU
计数器为零。静态物体和广告牌不在范围内。

### 第 2 阶段：保守地编译静态对象

使用权威的基本记录类型、参考标头标志、XESP 状态、
模范行为和资格界限； `statics` 是型号目录，不是
允许名单。从经过验证的固定 `STAT` 参考开始。省略未知，
最初是禁用的、依赖于启用的、可移动的、动画的和未解决的
具有记录原因的大参考案例，直到其后来的路线存在。
在使用这些 NIF 块作为层之前保留创作的 LOD 形状元数据
来源。承认经过验证的自动生成的传统 LOD 作为
附加源，然后将符合条件的不透明基元与簇进行比较
来自相同解析输入的层次结构。仅缺少创作变体
不得阻止该实验；不支持或无效的派生数据保留
具有显式诊断的已验证源路由。缺少源资产
保留遗漏，绝不沉默替代。

在阶段 0 可见性单元内编译兼容的材料批次，以及
保留出处和缺失参考检查员。保留每个对象的
批处理下的身份。已移动、已禁用、已选择或已交换材质
对象必须离开派生批次而不重复其游戏状态；
中提出的突变逃逸路径
[#185](https://github.com/Mudcrab-Team/mudcrab/issues/185) 需要自己的证明。
混合就绪对象组无法隐藏所有远处对象，因为只有一些对象
接近的替代品是可绘制的。 [混合合约](hybrid-object-lod.md)
定义实验的削减、后备和分阶段验收要求。

普通对象 LOD（`.bto`，可通过 `BSMultiBoundNode` 和
`BSSubIndexTriShape` 读卡器支持）可作为验证参考，而不是
来源。比较是建议性的并且每个世界空间：改变的加载顺序
世界空间的成功参考、静态或 LOD 模型使原版变得陈旧
引用，以便跳过世界空间的比较并按原样报告，并且
配置选项禁用或覆盖 modded 的参考集
安装。输入与普通版本不同的构建永远不会因不匹配而失败。

门：代表状态、运动、大参考、负网格、
边界装置没有显示出烘烤过时的物体或持久的重叠。部分和
来自相同输入的干净构建在语义上是相同的；源移动
使每个受影响的层失效。记录每层/类别的几何形状、纹理、
绘制、内存和主/反射通道成本。无支撑动态停留
省略；第四阶段拥有他们的代理路由。

### 第 3 阶段：添加树广告牌

编译对象路由树广告牌和有界的每个世界空间图集；测试
倾斜/下降变换、alpha 和 mip 覆盖以及图集失效。保留
不受支持的草 LOD 和 Skyrim `.LST`/`.BTT` 输出延迟。门：脚本化
匹配的近/远树叶捕捉保留了可接受的调色板（ADR-0009），
而 atlas、overdraw、内存和帧预算则保留在目标硬件上。

### 第 4 阶段：添加动态代理

为一组批准的启用实施状态跟踪单独代理
父母、发光/窗口覆盖和动画。保留脚本、碰撞、AI、
整个运行期间的库存和未经批准的移动。门：均为 XESP
反转状态、父错误/周期、加载/快速旅行历元、保存/重新加载、
和完整/代理切换传递，没有陈旧的视觉效果或重复的游戏玩法
影响。第三阶段的树叶并不是这条独立路线的先决条件。

### 第 5 阶段：证明综合结果

运行匹配的、重复的目标硬件活动以获得近场基线，
仅地形、静态物体、树木和动态效果。保留原始捕获，
相机路径、设置、硬件/构建 ID、分析器捆绑包和每层
质量/性能比较。门：声明的预算和视觉公差
通过，切换序列没有持久的漏洞或重复，并且有符号
评论接受新的脚本化远景捕获。不存在任何视觉准备要求
仅就 CI 而言。
