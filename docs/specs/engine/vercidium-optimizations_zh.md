# Mudcrab 高性能渲染和引擎优化

受到 **Vercidium**（定制高 FPS 引擎_Sector's Edge_ 的开发商）演示的关键引擎优化的启发。

---

## 1. 零状态更改 GPU 实例化 (`DrawMeshInstancedIndirect`)

### 创建引擎中的问题：

在原版《Skyrim》中，每棵树、岩石、建筑物或桶都会产生单独的 CPU 到 GPU 绘制调用。渲染 Whiterun 或茂密的森林每帧会产生数千个驱动程序状态更改，从而压垮 CPU 主线程。

### 泥蟹解决方案：

- **GPU 实例化批处理：**
  - 将相同的 glTF 模型分组（例如 `PineTree01.glb`、`WhiterunWall02.glb`）。
  - 向 GPU 发送**单个绘制调用**以及包含数组变换（`Matrix4x4` 位置、旋转、缩放）和材质变化标志的实例缓冲区。
- **间接绘图：**
  - 使用 WebGPU/Vulkan `draw_indexed_indirect`。 GPU 直接从 GPU 内存中读取绘制参数，无需等待 CPU 指令。

## 2. 空间网格划分和视锥体剔除

### Vercidium 概念：

将游戏世界划分为统一的空间块/网格单元，并在接触渲染管道之前消除不可见的几何体。

### 泥蟹实施：

1. **边界体积层次结构 (BVH) / 空间块：**
   - Skyrim 中的外部单元被划分为 32x32 的世界网格。
   - 在离线管道转换期间计算所有静态世界对象的轴对齐边界框（AABB）。
2. **GPU/作业系统视锥体剔除：**
   - 在将几何体发送到光栅化器之前，使用 Bevy 的人造丝工作窃取线程池并行测试 6 个摄像机视图平截头体平面的边界框。
   - 立即丢弃 80% 以上位于玩家视场后方或外侧的世界几何图形。

## 3. 硬件遮挡和分层 Z 缓冲区 (HZB) 剔除

###天际“透支”问题：

《Skyrim》经常渲染山脉、城墙或紧闭的门后面的物体，因为 CPU 遮挡检查很原始。

### 泥蟹解决方案：

- **分层 Z 缓冲区 (HZB) 剔除：**
  - 从前一帧的深度缓冲区生成低分辨率深度金字塔图。
  - 根据深度金字塔检查复杂对象（例如，Solitude 内的地牢或建筑物）的 3D 边界框。
  - 如果一座山遮挡了整个城镇，**完全跳过渲染城镇**。

---

## 4. 持久内存映射和零分配循环

### Vercidium 技术：

避免帧渲染循环期间的垃圾收集 (GC) 压力和堆分配。

### Mudcrab（Rust Native Advantage）：

- **60+ FPS 时的零堆分配：**
  - Bevy 中的所有 ECS 系统查询都重用预分配的数组缓冲区（`Vec::clear()` 而不是重新分配）。
- **`mmap` 持久缓冲区：**
  - 将转换后的 `.glb` 几何图形和 `SQLite3` 索引页直接映射到虚拟内存中。 CPU 从不跨堆边界复制资源缓冲区。

## 5. 优化技术汇总表

|优化技术|原始天际行为 | **泥蟹 Vercidium 式引擎** |
| :--------------------- | ：---------------------------------------------------------- | :------------------------------------------------------------------ |
| **抽奖** |每个静态对象 1 次绘制调用（数千/帧）| **批量实例化间接绘制调用**（< 100/帧）|
| **内存分配** |单元加载期间的运行时分配 | **预分配缓冲区 + `mmap` 零拷贝** |
| **扑杀** |基本距离和细胞剔除 | **视锥体剔除 + GPU HZB 遮挡剔除** |
| **脚本线程** |单线程虚拟机（Papyrus 堵塞）| **并行 Luau 纤维协程** |
