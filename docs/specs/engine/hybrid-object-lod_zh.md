# 混合对象 LOD

## 方向和状态

[比尔的 #203 提案](https://github.com/Mudcrab-Team/mudcrab/issues/203) 和
[泰勒协议](https://github.com/Mudcrab-Team/mudcrab/issues/203#issuecomment-6086560142)
支持范围内的集群实验
[#103 本机 LOD](https://github.com/Mudcrab-Team/mudcrab/issues/103)。
可接受的方向是基于网格优化器的间接聚类选择
抽签、分享本地居住权、资格、验证和安全交接。
将其与匹配视觉下自动生成的传统 LOD 进行比较
质量。地形、小网格、树木和无支撑材料保持其
适当的路径。反思是独立的工作。

共享资格和整体参考移交合同现在存在于
[`shared::lod::object`](../../../crates/shared/src/lod/object.rs)，具有显式
验证和陈旧一代检查。他们还没有创建引擎
实体、选择对象源或控制渲染器可见性。

下面的有效负载和运行时选择是供审查的拟议合同。本文档没有标注集群编译器、渲染器、分页
系统或 HLOD 实施完成。当前地形有效载荷及其
历史接受证据仍描述于
[LOD架构](lod-architecture.md)和
[编译器规范](../converters/lod-compiler.md)。本次修订修改
没有运行时默认值，并且不分配任何数字模式或格式版本。

现在有一个[离线比较适配器](../../../scripts/lod-experiment/README.md)
从相同的合格索引构建常规索引层和分组集群 DAG
使用固定网格优化器 v1.3 的 GLB 原语。综合测试检查准确
源剪切、统一组替换、边界/索引验证、显式
遗漏和重复性。它的 JSON 工件是实验性的，而不是
提议的运行时边车 ABI。它没有对世界参考资格进行分类，
验证保守错误或视觉质量，或实施管道阶段，
渲染器、分页或 HLOD。这些接受大门仍然敞开。

Bill 的转换器尖峰在 75 个转换后的普通网格上使用了 meshoptimizer v1.3，
1,487 个基元和 527k 个三角形，单线程释放，中位数为 3
运行。其报告的时间和规模估计证明了实验的合理性；预计的
全库和并行成本不是全转换器测量。
在该证据中，运行时帧时间仍然无法测量。

## 所有权和路线

|责任|合同|
|---|---|
|世界居留权 |现有的世界/单元/块生成、空间准入、共享预算、卸载和原点重新调整自身可用性。几何细节无法附加单元格。 |
|资格和状态 |解析的记录和运行时状态所有者决定启用和允许哪个引用。派生数据无法保持竞争状态。 |
|几何细节|为符合条件的常驻对象选择经过验证的来源、创作/生成的常规 LOD 或有效的簇切割。 |
|抽奖提交 |选择兼容的批次和功能支持的命令路径，而无需更改逻辑对象标识或覆盖范围。 |

从经过验证、无条件启用的外部 `STAT` 参考开始，
不透明的静态基元。需要权威的基本类型、参考标志、
启用父元数据、模型行为、转换和保守边界。
省略未知、最初禁用、有条件、可移动、动画和未解决
大参考案例从静态推导到其状态
并验证切换路由。仅最初禁用的过滤并不能
证明完整的启用父语义。

小基元将普通网格保留在测量阈值以下。保留
第一个集群实验中经过 alpha 测试的表面；轮廓和 mip
接受必须先于他们的入学。混合、蒙皮和动画网格
保留支持的普通/代理路由。树木使用专用的广告牌或
冒名顶替者；地形保留其 GLB/块路径。仍然缺少源资产
明确的遗漏。缺少创作的变体可能会使用经过验证的自动
一代；无效或不可用的派生数据保留可用的经过验证的
来源/常规路线。

## 共享对象生命周期

将资源标识与引用/放置标识分开。每个
渲染实例映射到其源对象、原始对象、材质和当前对象
世界一代。批处理无法删除该映射。派生表示
仅包含视觉数据；脚本、碰撞、库存、任务和 AI 保留
与运行时所有者。

拟议的突变合约
[#185](https://github.com/Mudcrab-Team/mudcrab/issues/185) 需要转义
单独启用/禁用、移动、选择和材料/模型的路径
变化。隐藏受影响的派生实例并让普通对象路径拥有
更改后的参考；使受影响的派生数据无效。绝不透露陈旧
等待更换时的几何形状。保存覆盖使用持久源
标识并且不序列化渲染器缓存。这种行为需要固定装置
在派生批处理或 HLOD 可以被接受之前。

准备就绪意味着所需的几何形状、材料和纹理已得到验证，
为相关视图准备并可绘制。驻留单元格或加载的根
仅靠这一点是不够的。混合就绪的近物体单独过渡，或者
作为明确完整的所有权单位；一个现成的模型无法隐藏一个
整个对象缺少覆盖范围或源单元格中不相关的引用。
保留符合条件的远表示，直到其相应的替代品出现
可绘制，没有持久的重复覆盖。

传统路由和集群路由共享生成保护、失效和
故障诊断。延迟/失败的资产、卸载、传送、世界变化
并且原始变基无法激活过时的完成。源移动和
材料/资格变更将使每个受影响的级别和位置失效。
在拥有流媒体策略下，瞬时重试仍然受到限制；失败了
可选几何图形永远不会重写源元数据或游戏状态。

## 转换器实验和建议的 sidecar

解决一组不可变的源原语、获胜材料和记录。
生成生成的常规 LOD 和簇候选对象
输入。在合适的情况下，保留经过验证的创作变体作为第三个选项。
Bill 的多达 128 个三角形簇和大约减半的组正在启动
参数；研究分组、简化限制和边界行为
而不是将这些参数声明为永久格式要求。

保持源模型 GLB 的权威性。将集群存储在可选的 sidecar 中
具有明确的格式版本和算法/设置标识。它的体现
必须包括源 GLB 和消耗的材质/纹理哈希、原始和
属性布局标识、编译器/meshoptimizer 修订版和有效负载哈希。
世界布局和参考状态保留在其拥有的世界合约中。

提议的序列化有效负载携带：

- 稳定的源基元/材质身份和索引/属性映射。
  保留受支持的材质路径所需的每个属性，包括
  UV、法线、切线和颜色。不要合并不相容的材料，
  alpha、发射或覆盖族。
- 保守的几何和误差范围，带有声明的单位和误差
  传播约定。家长/小组错误必须保守地考虑
  代表源详细信息。放置时的界限必须保持保守
  转变。界限有效性并不确定轮廓/材料质量。
- 非循环组替换链接和有效的完整剪切。分组
  简化可以重新聚类几何结构，因此独立的每聚类树
  父母不能假设。更换一个组需要将其全部更换
  覆盖范围；绘制任意父/子组合可能会破裂或重叠。
- 有效的顶点/索引范围，保留的锁定边界，以及完整的粗略
  每个承认的原始/材料单元的后备。验证退化，
  非流形输入处理、有限误差值和属性接缝。

检查字节顺序、整数宽度、对齐方式、长度、分配限制、
在实现加载器之前版本拒绝和校验和边界。
使用独立的黄金固定装置和畸形有效负载情况。网格优化器
demo结构不是一个稳定的存储ABI。文件名、数字版本和
任何数据库迁移都属于实施审核。

将 sidecar 与现有输入锁、哈希验证、分阶段集成
发布和回滚。请勿将保留的 GLB 重新标记为新生产者。
精确的消耗输入、格式、编译器、算法、设置和有效负载证明
控制重用。更改的输入重建受影响的派生数据；删除输入
或禁用一代删除拥有的过时的 sidecar。缺失、不兼容
或损坏的 sidecar 保留经过验证的源渲染并报告被拒绝的
路线。请求的实验明确报告不完整/错误状态；
后备渲染并不能证明生成成功。

根据可重复的清洁/增量结果对转换器实验进行门控，
源字节保存、属性/材料/边界检查和有效负载审核。
记录时间，缓存重用，字节和峰值内存，加上测量的几何，
原版和代表性模组资产的轮廓和材质错误。
没有专有源资产进入存储库。

## 常驻运行时实验

从常驻层次结构和保守的屏幕空间错误选择开始。
通过对象的变换和视图的投影缩放几何误差
和视口；测试镜像/非均匀变换和近平面相交。
大约一个像素是实验设置。选择完整合法的
替换组已准备好，没有遗漏覆盖或同时发生的情况
父/子重复。测试动态剪辑和过渡，而不仅仅是静止图像。

分别声明主覆盖、反射覆盖和阴影覆盖。使用按视图剪切或
保守的组合策略，具有明确的视口/错误和图层规则。
主摄像机剪切或遮挡结果无法建立另一个视图的覆盖范围。
保持阴影范围远离相机；衡量每个视图的成本。

启动时的探头适配器功能。具有 GPU 绘制计数的本机多次绘制
可以在支持的情况下使用； Metal 需要一个没有该计数的有界路径
变体，例如具有归零未使用命令的固定容量间接槽。
测量 CPU 循环成本，而不是假设与 Vulkan 或 DX12 同等。
不需要网格着色器或 64 位原子。

在接纳/细化集群对象之前保留完整的粗略覆盖范围。
当命令或选择容量耗尽时，替换整个有效组
具有可拉伸的粗切或保留经过验证的传统覆盖范围。从来没有
截断命令列表并删除几何图形。如果连最小的切口都无法贴合，
不要从后备路由转移所有权；报告未满足的容量。
重置绘制参数、强制边界并拒绝陈旧的世界/资源
提交前的几代人。检查溢出和回退诊断。

首先证明选择的正确性和相对于传统 LOD 的开销。
然后添加保守的平截头体/HZB 剔除和兼容的材质配料。
遮挡历史失效需要摄像机转动、传送和变基测试。
仅靠更少的三角形并不能建立更快的帧；抽签、批次和
选择/提交成本可能占主导地位。

## 后期分页和空间 HLOD

分页遵循常驻实验。保留可绘制的粗糙祖先，同时
加载更精细的几何页面，并负责磁盘读取、解码、上传，
居住和退休共享流预算。仅在之后承认详细信息
它的页面是可绘制的；错过、取消和驱逐选择有效的
较粗的切割。使用生成安全的页面标识和有界请求队列。
驻留层次结构还不是几何虚拟化。

空间 HLOD 是针对遥远定居点或其他群体的单独实验
其批量成本仍然很高。将其与匹配的每个对象的详细信息进行比较
质量。保留对象成员资格、突变逃逸、物质边界、
失效和可绘制切换。寻呼/HLOD 格式和预算保持不变
在测量的工作负载证明其合理之前，尚未做出决定。

使用源渲染、生成的常规 LOD 和集群 LOD 作为控件
以匹配的视觉质量。记录准确的源/构建/设置/硬件
身份、启动、遍历、镜头转动、传送/恢复和长时间
会议。报告 FPS 和帧百分位数、CPU/渲染线程/GPU 成本、
绘制/三角形、内存、上传和可绘制覆盖范围的时间。保留现有的
验收预算；不可用的 GPU 计数器仍然不可用。合成的
固定装置和静态捕获无法建立整个游戏或目标硬件
接受。

保持转换器/运行时集群实验、分页和 HLOD 选择加入，直到它们
自己的类别和后端门通行证。地形的现有默认值保持不变
分开。树、动态代理和地形形状接受不遵循
通过不透明静态集群检查。单独决定任何 Bevy 0.20 迁移
从这个实验的格式和后端审核来看。

## 独立反思里程碑

[#203](https://github.com/Mudcrab-Team/mudcrab/issues/203#issuecomment-6075563397)
报告删除反射视图后下游 SSR 增益。那些结果
不要预测第一个本地端口的增益，因为它保留了平面
纹理作为小姐填充。

1. 具有平面回退的 SSR：验证附近反射、前向/水反射
   集成、颜色/深度输入、移动相机伪影和集成
   主视图/图层设置的成本。
2. 具有视差校正探头且禁用平面相机的 SSR：验证
   离屏/隐藏反射、探头放置/新鲜度、后备质量、
   捕获引起的加载停顿和测量的视图成本消除。

探针捕获和刷新必须携带源/世界身份和有限负载
工作。保持固定的立方体贴图/天空回退策略明确。每个里程碑依然存在
设置控制直到其视觉和性能门通过。反思
工作既不会阻碍地形/对象 LOD，也不会打开它们的接受门。

## 实现离线控制导出

选择加入 `--export-controls` 实验现在编写整个模型源代码，
来自同一承认的传统和完整的统一簇切割 GLB
基元。它保留源顶点字节、访问器布局、节点变换、
材料和场景所有权。省略的基元保留其源几何形状；
嵌入本地图像，包括仅保留使用的依赖项
基元。清单对每个控件进行哈希处理并记录保留的覆盖范围，
每个基元三角形计数和选定的终端深度。

独立解码验证索引选择和源有效负载/元数据
保存。这为下一个比较门提供了可渲染的控件。
它不实现自适应视图剪切、运行时 sidecar ABI、分页或 HLOD，
并且不证明保守错误或渲染质量。香草和改装
资产集仍然需要独立的出处、相同的相机/材料
设置，以及促销前匹配质量的视觉和时间比较。
