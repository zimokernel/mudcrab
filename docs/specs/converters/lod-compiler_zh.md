# LOD 块编译器

离线编译器将 `references` + `statics` + 单元缓存转换为
空间 LOD 块。使用规范路径、不可变的输入边界，
分阶段输出、经过验证的构建身份、内容哈希失效以及
模式版本化清单。运行时在运行时持有共享同级锁
读取资产目录。转换之前需要非阻塞排他锁
阅读先前的包并通过发布保留它；活跃的读者
拒绝转换工作之前的构建。符号链接的输出目录是
被拒绝了。中断的交换仅恢复目的地拥有的、经过验证的
备份。同级发布记录密封清单和生成的文件；
不明确的旧备份需要手动恢复。清理验证新的
删除其拥有的前身之前的包。验证错误识别文件，
块和形状。

CLI `--no-lod` 在正常转换和元数据重建中都会跳过此编译器。
它发布带有空 LOD 表且没有 LOD 清单的完整详细地形/世界数据
或生成的块。默认转换构建 LOD 并仅重用未更改的块
当当前输入指纹和先前的有效负载验证时。参见【管道运行与恢复】(pipeline.md#7-command-line-progress-interruption-and-resuming)
用于相同输出锁定、只读安装和无主备份。

新的 CLI 运行和 `PipelineConfig::new` 使用 GPU 编码生成地形
地图集。 `--lod-encoder cpu`选择CPU编码。普通源纹理使用
独立的`--texture-encoder`设置，仍然默认为CPU。
在没有 `lod_texture_encoder` 的情况下反序列化旧配置可保留 CPU LOD
编码而不是改变其输出配方。

实现的编译器生成地形 LOD。下面选择对象源
描述第二阶段的工作；可选的聚类实验
[混合对象 LOD](../engine/hybrid-object-lod.md) 是一个提议的扩展，
不是已实现的输出或新的默认值。

## 输入

- `references`（放置、旋转、缩放、`radius_override`）、`statics`
  （模型路径、边界）、外部 R 树、单元缓存地形。
- 每个世界空间 LOD 起源（新 `worldspaces` 列；需要
  GEOM-02，今天失踪）：使用有效的 `lodsettings/<worldspace>.lod`
  sidecar 或自定义世界的明确起源。否则跳过那个
  世界的 LOD 存在可操作的错误；永远不要假设原点为零。
  归档提取后从分阶段的规范 VFS 中解决 sidecar
  和松散的覆盖。 Skyrim 的 16 字节布局是两个小端 `i16`
  原点后跟 `i32` 步幅、最小级别和最大级别，每个
  [xEdit的阅读器](https://github.com/TES5Edit/TES5Edit/blob/dev/wbLOD.pas#L453)。
  这些字段不是宽度/高度。本地层和源小区覆盖
  保持独立于天际的步幅和水平范围。
- 参考标头标志和启用状态列（新；`XESP` 父级 +
  反转标志），在转换时提取，以便资格和运行时
  查询不依赖于每个查询的 blob 解析。
- 规则集：显式记录规则，然后组件/类型默认，然后
  有理由地省略。每一个决定都记录了胜利者、规则、模式和
  后备原因（ARCH-02、RULE-03）。

## 选择

每层源选择：地标可以在第 4 层重复使用其完整的 GLB，而
杂波在第 16 层（GEOM-03）之前消失。编写的 `_lod` NIF 变体
如果存在，则按约定进行匹配。供应商解析器读取
`BSLODTriShape.lod_sizes` 和 `BSSubIndexTriShape` 段数据，但
当前导出器仅将每个块的基础 `BSTriShape` 传递给通用块
网状路径。这些每级计数和段范围都会丢失。保存和
在使用这些块作为特定于层的源之前验证它们。失踪
source 意味着有原因的省略，从不沉默的近匹配替换（RULE-05）。
已验证自动生成的常规 LOD 和簇层次结构
也是混合实验下的候选来源。缺少作者
变体并不意味着缺少源几何体。生成两个候选人
来自相同的已解析原语并将其源 GLB 保留为可用
后备；拒绝无效的派生数据并给出理由。这并不授权
远距离批次中未经审查的完整细节替换。
第一个静态通道仅允许经过验证、无条件启用的固定
`STAT` 参考文献。 `statics`是型号目录，不是资格标志；
未知、最初禁用、XESP 控制、可移动、动画和
未解决的大参考案例将被省略并给出原因，直到经过验证
存在单独的代理或切换路由。

## 块构建

- 以双精度转换，然后发出块局部坐标；
  使用形状变换 (GEOM-04) 变换法线和缠绕。
- 每个 GLB 块中的每个源单元发出一个稳定的节点，独立地
  可隐藏的地形和对象组。每个组下的分区批次
  渲染兼容性（材质系列、Alpha 模式、叠加标识）、
  不是按纹理文件名（MAT-02）。
- 0-1 之外的 UV 回落到直接纹理；绝不夹紧重复
  没有保留转换的 UV (MAT-04)。
- 从静态输出中去除碰撞和场景图额外内容；动画
  效果资源则采用代理路径 (GEOM-07)。
- 破坏性优化（重复数据删除、隐藏面删除）是单独的
  禁用；隐藏面去除使用容忍和保守测试
  （GEOM-08/09）。地形只能隐藏具有相同形状的三角形
  保守主义；桥梁和洞穴永远不会在地形上被删除。
- 引用全部位于无法到达的空间中的块只能被修剪
  针对可达视点集，采用无修剪参考模式
  用于比较（GEOM-10）。

## 输出

块有效负载是包含空间索引的数据库的 GLB 文件，
根据 ADR-0010：块键 `(world, tier, anchor)`、边界、批次列表、
内容哈希、清单引用以及世界范围内的 R 树
用于范围查询。每个块都有保守的界限，一个材料批次
列表、用于切换的源小区/组节点标识 (GEOM-05) 和清单条目：
输入、规则集、设置和编译器版本的内容哈希
(BUILD-01/02)。 DB、清单和块记录共享一个构建标识；
仅在每个引用的有效负载验证后才发布。 `lod` 重塑
附带世界数据库版本提升。

组合实现使用转换器模式 27 和世界模式 9。世界模式 5
属于草数据； LOD表在模式6中引入。仅验证当前
生产者 27 网格可以在正常转换期间重复使用。生产者 26 组合修正后的 TXST
列、纹理语义和一字节 XESP 标志，并使 GLB 与兼容版本保持不变
生产者24；生产者 27 将碰撞形状和图层添加到 GLB 碰撞数据中，因此不会更早
生产者的网格仍然可以重复使用。
《制作人 23》的分享者为
刚体动力学改变 GLB 有效负载之前和之后的源表面导出器；
其编号无法证明当前的网格合约。所有早期制作人（12-24 和 26）
重新生成 GLB 和纹理，仅保留经过验证的脚本/存档摄取。
数字排序不允许重复使用。单独的 #194/#196 候选者都使用了 25/8
对于不同的合同；联合生产者分配 26/9 并拒绝那些
资产或元数据重用的模糊候选身份。
配置证明包括编码器选择和 GPU 质量，而仅批量大小
改变日程安排。仅元数据保留的字节保留显式的原始生产者，
配置、清单和输出哈希值；它们保留的纹理和网格未经过认证
当前生产者字节。随后的正常转换会重新生成每个早期的生产者
纹理和 GLB。
纯草 schema-5 世界在没有 LOD 表的情况下仍然可读。

组合这些分支时，请有意解决缓存和元数据门：
单独的数字排序并不能证明照明网格是兼容的
与 LOD 分支。每个独立的产出合同变更都必须分配新的
生产者/数据库身份并解决显式兼容性门；更新运行时，
启动器、清单和捕获门一起。现有
下面的本地证据描述了其原始制作者并且是历史性的。
Main的转换器模式16识别碰撞感知资产；保留资产
在仅元数据重建期间保留其生产者模式/配置。

GLB 顶点和访问器边界是块本地的，相对于块根。
数据库边界和 R 树 XY 边界是世界空间创建单位：翻译
`(origin + anchor * tier_side_cells) * 4096` 的块局部 X/Y 范围； Z
是不变的。切勿将块局部坐标索引为世界空间边界。

### 建议的对象边车

保持地形 GLB 和空间索引契约。混合实验增加了
GLB 模型旁边有一个可选的、独立版本的集群 sidecar。
已解决的世界数据和模型 GLB 仍然具有权威性； sidecar 是派生的
渲染数据。他们的存在不能改变参考资格、世界
居住权、游戏所有权或地形编译。

sidecar 合约必须识别源 GLB 字节、消耗的材料和
纹理输入、基元/属性布局、编译器和网格优化器
修订、设置、层次结构/错误约定、有效负载版本和输出
校验和。保留稳定的源原始/材料身份、索引和
属性映射、保守几何和误差界限、组替换
链接，以及完整的后备剪辑。分组简化可能会重新组合其
输出；验证者不能假设每个集群都有一个独立的树
父母。验证完整的组替换，没有重叠或缺失
覆盖率、有效索引、有限误差、非循环链接和保留锁定
边界。保守的界限并不能证明轮廓或材料质量。

在运行时消耗之前检查序列化的 ABI：整数宽度、
字节顺序、对齐方式、长度、分配限制和未知版本
处理需要独立的黄金装置和格式错误的有效负载检查。
不要将 meshoptimizer 的内存中演示结构序列化为隐式结构
稳定的格式。实际文件名、版本值和任何数据库迁移
在实施变更中分配；该提案没有分配任何资源。

比尔的大约128个三角形簇和分组减半正在开始
参数，而不是兼容性要求。将它们与生成的进行比较
使用相同源输入以匹配质量的传统 LOD。记录
转换时间、缓存重用、有效负载大小、内存、属性、边界行为、
和轮廓/材料错误。他的小转换器尖峰和线性估计
是研究证据，而不是该编译器阶段的测量结果。

将可选输出集成到现有的不可变输入、哈希、暂存、
锁和发布边界。丢失、陈旧、损坏或不受支持
sidecar 必须保留经过验证的源/传统渲染可用，并且
记录集群路由不可用的原因。请求 sidecar 的构建
输出无效后无法报告该类别已完成；它的严格/错误
政策必须明确。重用需要精确的消耗输入、算法、
设置、格式和输出证明。删除输入或禁用生成
删除拥有的过时的 sidecar。相同的干净和增量实验
必须同意而不更改保留的模型字节或生产者出处。

## 增量构建

参考移动传播到每个受影响的层、世界副本和变体
（构建-03）。图集像素更改仅在 UV 布局和
材料合同不变（BUILD-02）。部分构建必须等于
语义上干净的构建或被标记为不安全（BUILD-04）；空运行影响
报告先于昂贵的再生（BUILD-05）。
恢复重建有效的VFS并重新生成世界数据库，
单元缓存、集成报告、起源、块索引和构建标识。块有效负载
可以从先前发布的包中重用，并在现有资产锁定下保存。
`lod-manifest.json` 记录显式地形编译器修订和每块输入
指纹。指纹覆盖单元 ID/网格、精确高度/VCLR/层/不透明度数据、
赢得扩散路径和 DDS 哈希、起源、层级、平铺和生产者身份。
重用还根据当前源派生的边界/单元检查旧索引，并且
验证有效负载哈希和 GLB/KTX2 结构。遗留证明缺失、损坏
有效负载或更改的消耗输入会重建受影响的块。不相关的插件
编辑可以保留有效负载，而最终身份仍然包括当前订购的
插件哈希和设置。 `--invalidate-cache` 还绕过 LOD 重用。

每个阶段都会读取并验证一个对齐的单元缓存快照。漫反射图像
跨世界和 FormID 共享解码的创作 mips 和准备好的层图像；
在发布之前重新检查源字节。块准备几何形状和
并行地绘制图集像素，然后对一批有界图集进行编码。每个提供的 mip 都经过编码
一次；有界图集本地缓存一旦使用就会编码相同的 4x4 RGBA 块
相同的上游 UASTC 2 级例程和转码提示。 KTX2 编写器是
与GPU路径共享，级别表使用编码后的基础元数据。
默认 GPU 路径将那些相同创作的 RGBA mips 提交到 GPU UASTC
编码器。显式CPU配方保留现有指纹；图形处理器
配方添加了其编码器版本和质量。 GPU 后备块仍然有效
发布了有效负载，但省略了可重用的输入证明，因此稍后的 GPU 运行会重试
他们。显式 CPU 选择产生 CPU 配方及其重用证明
相反。更改 LOD 编码器不会使普通网格或纹理失效。
GLB 程序集在 atlas 编码后并行运行，然后序列化
数据库发布。
当此输出配方更改时，地形编译器版本也会更改。只有一个
一次保留 CPU-worker 大小的一批有效负载。世界索引是
事务性：稍后的内容失败会删除早期的批次有效负载和滚动
回到整个世界。取消、来源突变和出版物/数据库
错误仍然是致命的。进度消息公开世界内的块计数，并且
`PipelineReport.lod_cache_hits` 记录已验证的重用（旧报告中的默认值为零）。

经过日记验证的普通资产仍然可以重复使用；省略世界/块并删除
设置无法在分阶段元数据或有效负载中保留。编译器修订属于
LOD 构建/指纹识别；普通生产者 24 字节保留其出处。

  重新生成的原始哈希/大小、精确记录的剪枝集和精确
  保留剪枝后哈希/大小。记录重播出处；拒绝其他编辑。

  原始保留的配置哈希并再次验证。失踪
  仅元数据输出中的生产者配置拒绝元数据重用
  正常转换缓存重用；从已核实的原始资产中恢复。
- LOD-V8：源删除后恢复的转换等于干净的构建
  资产路径、字节、清单条目和纹理修剪决策。删除
  过时的暂存 GLB/KTX2/Luau 文件和之前的纯元数据来源
  重建；文件存在本身并不是当前输入的来源。保存
  当前输入输出匹配暂存日志源/架构/配置
  和字节；仅在重建有效 VFS 后才修剪孤立路径。
  在重新转换之前删除无效的分段输出；源读取/转换
  失败无法在新清单之外发布过时的 GLB/KTX2/Luau 字节。
  即使没有快速失败，删除失败也会中止发布。
- LOD-V9：地形 LOD 带有来自获胜 LAND 的烘焙漫反射反照率
  BTXT/ATXT/VTXT 层和当前规范的 DDS 输入。匹配附近地形
共享 `LAND_TEXTURE_REPEATS_PER_CELL` (24)，有序六层限制，双线性不透明网格，
  归一化叠加总和、线性光漫反射混合和线性 VCLR 色调。
  烘烤一次着色；嵌入式 sRGB KTX2 图集、mip 链和填充象限 UV
  属于有效负载校验和。丢失/无效的材料输入会跳过世界的
  LOD 具有明确的诊断功能，绝不替代发明的底色。
  仅元数据重建解决当前存档/松散地形 DDS 输入；
  保留的纹理源哈希在烘焙之前必须一致。
  无层源象限通过源 VCLR 保留中性漫反射，
  匹配近地形；它们与未解决的参考材料不同。
- LOD-V10：每个 LOD 象限保留所有 17 个源高度样本
  边界，与层无关；相邻的完整/LOD 和 LOD/LOD 源边缘
  当源高度重合时重合。共享编译器/运行时常量
  需要 65 个顶点和 192 个索引：64 个周边样本加上中心。
  非线性边缘夹具验证源相等性和层/单元一致性。
- LOD-V11：填充图集采样不能包括相邻的图块或未使用的图块
  任何发射的 mip 处的 Atlas 空间。具有两像素装订线和固定的 GLB UV，
  仅从线性光对齐框下采样发出级别 0..2。较小
  全局生成的 mip 违反了切片隔离；远处的混叠仍然存在
  视觉接受度问题，而不是完全正常/材料平等的证明。

## 拥有阻塞编译

地形编译在 Tokio 的阻塞池上运行，具有自己的配置，
路径、插件证明和报告状态。异步调用者可以耗尽进度或
在世界事务期间当前线程运行时的请求取消。
正常转换会在工作线程中保留其运行时输出和修复租约；
元数据重建保留其源读租约和目标写租约。
挂断呼叫者信号取消而不释放这些租约，同时
工人仍在运行。取消也会中断完整的进度通道
等等。事务仍然检查有界批次之间的取消、回滚
一个未完成的世界，并拒绝出版中断或混合输入的内容
构建。工作人员可以在停止之前完成当前批次；取消
不会终止正在进行的 GPU 调度或 Rayon 任务。
