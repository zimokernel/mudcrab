# DDS 到 KTX2 纹理转换

Mudcrab 提前将提取的 Skyrim DDS 资产转换为 KTX2 容器。两路输出
配置文件存在：

|输出配置文件|纹理政策 |
| ---| ---|
| **桌面/本机**（默认）|在 KTX2 内部保留兼容的 DDS 块格式；仅在需要时进行转码。 |
| **便携式后备** | UASTC 适用于没有本机映射的源，具有匹配的超级压缩。 |

桌面配置文件逐字节保留 BC1-BC7、R8 和 RGBA8 有效负载：无重新编码丢失，
没有 2x BC1/BC4 增长，运行时直接采样原始 GPU 格式。

## 语义编码契约

颜色空间源自使用槽，而不是源自文件名后缀或文件扩展名。

|槽语义|编码 |
| ---| ---|
|基色、自发光、镜面/光泽、细节、环境立方体 | sRGB 颜色 |
|法线切线空间，法线水流 |线性法线 |
|金属/粗糙度、遮挡、高度、掩模、内层、灰度 |线性数据|

该转换器从每个已发布的 GLB 以及 `texture_sets` 和水行中收集语义
世界数据库。通过不兼容的类到达的纹理被拒绝，因为一个 KTX2 URI
不能安全地表示两个传递函数。未分类资产保持线性/数据而不是
从他们的名字就可以猜到。

## 支持的 DDS 拓扑和格式

- BC1、BC2、BC3、BC4、BC5、BC6H 和 BC7 2D 纹理由转换夹具覆盖。
- 六面立方体贴图和可到达的 3D 体积纹理保留其拓扑。
- 普通纹理数组被明确拒绝。
- 所有创作的 DDS mip 级别均独立保存；转换器不取代
  他们有一个生成的链。失去源级别的表示是硬失败。
- RGBA alpha 为不透明、剪切和混合材质消费者保留。

## 本机块保存

可保留的源（FourCC DXT1-DXT5 加上 DXGI BC1-BC7、R8、RGBA8、2D/立方体贴图/体积）映射到
他们的原生 `VkFormat` 与 sRGB 与线性取自插槽语义，而不是文件名。每个
mip 级别的字节逐字复制；立方体贴图级别在每个面聚集一个切片，体积级别保持不变
他们的深度切片。 DFD是根据目标格式生成的。未映射的 DXGI 格式和 L8 下降
返回 UASTC 路径。

具有全字节通道的未压缩 2D 纹理（24 位 B8G8R8、X8R8G8B8、A8R8G8B8、A8B8G8R8
和其他 RGB(A) 位掩码布局（DXGI B8G8R8A8/B8G8R8X8）未使用 UASTC 重新编码，这
很慢。它们的解码 mip 在 CPU (`intel_tex_2`) 上进行块压缩并存储为本机
每个插槽中的 BC7：布局具有 Alpha 通道时的快速 Alpha 配置文件、快速不透明
否则轮廓（视为不透明：alpha 等于或接近 255，因为 BC7 模式 6 可以着陆一步或
下面有两个）。 sRGB 与 UNORM 来自插槽编码。 BC7是什么运行时
将以前的 UASTC 输出转码到桌面上，因此 GPU 内存不会改变。就像
保留 BC 源，此输出属于桌面配置文件：不带 BC 支持的 GPU（Adreno
在 Android 上）无法对其进行采样，并且便携式配置文件必须对这些纹理和
相反，将 BC 源保留给 UASTC。尚无转换器选项选择该配置文件。

每个 mip 通过复制边缘像素填充到整个 4x4 块，因此 1x1 和奇数大小的 mip 保留
该块计算容器期望的数量；已经填充整个块的行被压缩，其中
他们撒谎。与字节复制格式不同，输出是有损的。它在一台机器上是确定性的，但是
不跨 CPU 代：`intel_tex_2` 在运行时选择其 ISPC 内核，而 AVX2 内核
（融合乘加）可以选择与 SSE2、SSE4 和 AVX 内核不同的块，这
彼此同意。输出哈希仅与同一运行写入的输出进行比较，所以这
不影响缓存或验证。行是紧密的或 DWORD 对齐的，这
仅 24 位布局有所不同：mip 0 标头间距精确命名其中一个决定
每个mip；否则，精确对齐的链大小的有效负载意味着对齐的行，以及任何东西
else 读得紧，如 `image_dds` 读取的那样。最后一个 mip 之后的字节将被忽略。一个纹理，其
有效负载比其链短回落到 UASTC 而不是失败，并且打包尝试的
原因与后来的失败错误有关。这些布局的立方体贴图和体积，16 位
格式、调色板和 L8 也回落到 UASTC。在 `--texture-encoder gpu` 下这些纹理是
而是在 GPU 上编码为 UASTC。

组合的本机 BC DDS、创作的表面输入和更正的 TXST 语义生成器已抵达
转换器模式26；当前的生产者是 27（碰撞覆盖），具有相同的纹理合约。
纹理集TX02选择环境掩模线性数据，
TX03 发射颜色、TX04 高度线性数据和 TX05 环境立方体颜色。
Schema 18 独立分配给原生 BC DDS 和镜面反射变化，因此它的数字标识
无法证明网格或纹理兼容性。已知模式 12-24 和 26 的清单重建所有
纹理、GLB 和世界输出。生产者 24 的明确兼容的 GLB 合约以生产者结束
27，它更改了 GLB 冲突数据，因此早期的 GLB 不再可重用。源/配置/输出验证
脚本和存档摄取仍然可重用。从 schema 22 开始的配置哈希包括 CPU/GPU
编码器选择和 GPU 质量； GPU 批量大小仅更改调度。分阶段输出
需要准确的当前模式 27 出处。早期的纹理字节永远不会提升到当前的
输出。仅元数据重建保留原始资产来源，并且不修复旧编码。

字节保留在装置中的每个 mip 级别上断言，并且 Bevy 引擎测试加载本机
通过 `ktx2_buffer_to_image` 验证 GPU 格式、尺寸和 mip 计数进行输出。

## Per-mip Zstandard 超级压缩

每个输出级别（本机或 UASTC 后备）在其面和之后均经过 Zstandard 压缩
切片组装成完整的关卡。压缩永远不会独立应用于面：
独立压缩的面长度不同，会破坏立方体贴图级别的组装。
KTX2 标头携带方案 2，压缩后的 `byte_length` 和 true
每级 `uncompressed_byte_length`； `texture_zstd_level`（默认6，0禁用）设置
级别并参与清单配置哈希。没有率失真调谐
应用：此阶段是无损的，任何有损调整仍然是单独的质量决策。

运行时启用 Bevy `zstd_c`，因此 `ktx2_buffer_to_image` 在之前解码每个级别
格式映射。 Bevy 引擎测试断言超压缩和纯输出解码为
相同的图像字节。

## 发布和验证

可保存的资源保留其区块；后备源将每个 mip/face/slice 解码为 RGBA 并
编码为 UASTC。 UASTC 仍然是每个语义类的后备，因为 Bevy 运行时
path 一贯支持其 KTX2 超级压缩合约。之前
输出被自动重命名到位，转换器验证：

- KTX2签名、传递函数和图像级表；
- 相对于 DDS 的宽度、高度、深度、mip 计数、面计数和层计数；
- 编码字节长度和确定性 SHA-256；
- 扩展了 RGBA 字节大小、颜色模型和超级压缩模式。

验证/发布失败后，临时文件将被删除。批量转换是分阶段进行的
仅当每个受支持的输入都进行转换并且每个生成的
工件验证。安装的游戏数据包含但转换器无法发布的纹理
运行仍然失败；游戏数据不包含其源的纹理参考则不会。的
转换器会删除这些引用 - 包括基色 URI - 以及指向的每个材质槽
从发布的 GLB 中查看它们，记录该网格下的下降路径
`pruned_texture_references` 条目位于 `conversion-manifest.json` 中，并且仍然发布清单
使用 `complete: true`，因此网格使用确实存在的贴图进行渲染。
独立的纹理闭合报告使用格式版本 3，记录转换器模式和
每个纹理的元数据相同，并且从不报告缺少所需资源或转换的成功
失败。

## 往返接受

自动装置通过桌面 BC7 路径对生成的 UASTC 进行转码并再次解码。
他们验证了剪切 alpha 保留了透明和不透明区域、不对称切线空间
法线向量保持 X/Y 方向和 Z 强度，并保留不同的创作 mip 颜色/alpha
在他们原来的水平上。安装的立方体贴图和体积装置也可以通过
`MUDCRAB_DDS_FIXTURE` 和 `MUDCRAB_VOLUME_DDS_FIXTURE` 测试环境变量。
